Expand description

The receiver of the actions of the protocol state.

The state calls this while it handles an event, and never waits on it. A runtime may drop only some messages, see IO::send.

fn send(&mut self, peer: PI, message: Message<PI>) -> Option<Message<PI>>

Sends message to peer. Returns the message if the queue dropped it.

A queue may drop a message for which Message::is_droppable holds: a payload or an announcement, to a slow peer that stays connected. The state then announces the message to the peer, which can request it once it has room. It returns None if the message is queued, or if the peer is gone.

The queue must not drop any other message, such as a membership message, a prune, or a graft. The two peers would then disagree on their links, and neither would notice. If the runtime cannot queue such a message, it closes every connection of the peer, drops what it queued for the peer, and hands InEvent::PeerDisconnected to the state. Both sides then start over.

fn connect(&mut self, peer: PI)

Connects to peer without a message.

The runtime answers with InEvent::PeerConnected once a connection to the peer exists, so that a message goes out at once. If the connection fails, it reports InEvent::PeerDisconnected. A topic wants the connection until the peer is connected.

fn filter(&mut self, _message: FilterContext<'_, PI>) -> Option<Verdict>

Asks the application whether to deliver and forward a received message.

Returns None if there is no filter, which accepts every message. The state calls this once per message id and topic, before it caches, forwards or delivers the message.
